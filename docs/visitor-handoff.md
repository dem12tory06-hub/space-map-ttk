## Что работает

- Существующий маршрут `/map/<venueId>` подключён к `mountVisitor(container, { venueId })`.
- Загрузка сохранённой площадки через `GET /api/venues/<venueId>`, без ключа организатора.
- Подложка JPG/PNG, её сохранённые placement/visible/opacity, все пять типов объектов и места.
- Переключение этажей; поиск по названию без учёта регистра на текущем этаже.
- Выбор из списка или на карте открывает название, категорию и описание, выделяет и центрирует место.
- Приближение/отдаление кнопками, колесом и жестом двух указателей; перемещение перетаскиванием.
- Клавиатура: фокус на области карты, стрелки, `+`, `-`, `Home`. Места и список доступны через Tab/Enter.
- «Показать весь план», включая выступающие за рамку повёрнутые объекты.
- Состояния загрузки, 404, ошибки сети/сервера с повтором, неподдерживаемого ответа, пустого этажа/поиска, отсутствующей/скрытой/недоступной подложки.
- Только просмотр: нет запросов записи, полей редактирования, токенов или сохранения в браузере.

## Фактический формат входных данных

Источники истины: `server/venue-store.js`, `server/app.js`, `src/constructor/constructor.js` в этой копии. Старые README и документы состояния описывают заглушку и частично устарели. Этот документ описывает только добавленный viewer.

Ответ GET — объект площадки `{ id, name, revision, createdAt, updatedAt, floors }`, не обёртка `data`.
У этажа: `{ id, name, plan, places, panoramaPoints, routeNodes, routeEdges }`.
У плана: `{ id, width, height, elements, background? }`.

Элементы: `{ id, type, name, x, y, width, height, rotation? }`.
Типы: `zone`, `table`, `stand`, `stage`, `partition`. Зоны рисуются под остальными объектами, как в конструкторе. Поворот в градусах вокруг центра прямоугольника, по часовой стрелке в экранной системе координат.

Места: `{ id, type, name, category, description, x, y }`.
Типы: `entrance`, `registration`, `service`. Пустое описание заменяется текстом «Описание пока не добавлено». Все названия и описания вставляются как текст, а не HTML. Существующие ID используются без преобразования; номера маркеров — только подписи в порядке массива, не новые ID.

Координаты и размеры нормализованы относительно **всего плана**, начало в левом верхнем углу. Фактический холст конструктора — **1000×600**. `plan.width`/`plan.height` сейчас обычно равны 1 и не задают соотношение сторон. Viewer использует те же 1000×600. Переход на произвольные размеры плана требует совместного изменения конструктора, серверной проверки placement и viewer.

Подложка:

```json
{
  "id": "background-id",
  "mediaType": "image/png",
  "width": 500,
  "height": 300,
  "visible": true,
  "opacity": 0.7,
  "placement": { "x": 0.1, "y": 0.15, "width": 0.7, "height": 0.7 }
}
```

`background.width/height` — пиксели исходного файла. `placement` — нормализованный прямоугольник внутри плана: пример означает x=100, y=90, ширину 700 и высоту 420 в координатах конструктора. Viewer не растягивает такую подложку на весь план. При отсутствии placement старое изображение вписывается по центру с сохранением пропорций, точно как в текущем конструкторе.

Изображение загружается отдельным GET:
`/api/venues/<venueId>/floors/<floorId>/background/<backgroundId>`.
В URL каждый ID кодируется `encodeURIComponent`. Нет base64-подложки в JSON и нового формата сохранения.

## Подключение и перенос в общий проект

1. Перенести четыре файла `src/visitor/` из списка ниже.
2. В ветке маршрута `/map/<ID>` файла `src/main.js` импортировать `mountVisitor` и вызвать его с декодированным ID; убрать класс `shell` у контейнера. `/map/demo` зарезервирован под явно обозначенный локальный пример.
3. Добавить CSS в `index.html` и четыре публичных ресурса в allowlist `server/app.js`. Не заменять файлы другого участника целиком — объединить только эти точки подключения.
4. Использовать тот же сервер и DATA_DIR, где конструктор сохранил площадку. Ссылка «Поделиться» уже содержит правильный `/map/<ID>`; изменять сохранение или авторизацию не требуется.
5. При подключении к будущему SPA вызвать возвращаемую `mountVisitor` функцию очистки при уходе с экрана: она отменяет запрос, обработчики и ResizeObserver.

Фраза конструктора «просмотрщик ещё не подключён» остаётся в его старой подсказке. Файлы конструктора намеренно не менялись; при объединении участник конструктора может обновить эту подпись.

## Локальный запуск

Node.js 24, внешних зависимостей нет; установка пакетов не требуется.

```powershell
Set-Location D:\space-map-visitor
node test/visitor-demo-server.js
```

Скрипт использует только `D:\space-map-visitor\data\visitor-demo`, создаёт отдельную демо-площадку в **существующем хранилище**, сохраняет PNG и запускает стандартный сервер на свободном порту (PORT=0), привязанный к 127.0.0.1. Организаторские записи через этот сервер отключены: ключ ему не передаётся. Каждый запуск создаёт новый ID и печатает точный адрес. Ключ для проверки посетителя не нужен.

Запуск этой задачи оставлен доступным:

**http://127.0.0.1:50247/map/e6a8808f-1257-4a34-96be-213829a3d5fd**

Это сохранённая **демо-площадка**, читаемая через настоящий API, а не импорт реальных площадок команды. Её имя содержит «Демо». Подложка специально занимает только часть плана для проверки placement.

`http://127.0.0.1:50247/map/demo` — отдельный статический пример того же формата без подложки; на экране явно написано «не загружен из API». При ошибках настоящего API viewer никогда не подставляет этот пример автоматически.

После остановки текущего процесса можно продолжить чтение уже созданного демо:

```powershell
$env:DATA_DIR = 'D:\space-map-visitor\data\visitor-demo'
$env:BIND_HOST = '127.0.0.1'
$env:PORT = '50247'
node server/index.js
```

Если порт занят, выберите другой или PORT=0 и используйте напечатанный адрес. Чужие серверы не завершайте. Не запускайте копию с общим DATA_DIR по умолчанию, если там работает другой агент. Для собственной новой площадки запускайте конструктор с отдельным DATA_DIR и локально заданным ORGANIZER_TOKEN; вводите ключ только в локальном поле «Ключ доступа организатора», не в чате и не в исходниках.

## Простая ручная проверка

1. Открыть адрес сохранённого демо: видны подложка, объекты и четыре номера.
2. Нажать №2: появятся «Регистрация» и описание, маркер получит жёлтую рамку.
3. В поиске ввести `ВЫСТ`: останется «Выступления». Нажать строку — выделится №3 и откроется карточка.
4. Нажимать +/−, прокрутить колесо над картой, перетащить план. Подложка и объекты должны оставаться совмещёнными. «Показать весь план» возвращает общий вид.
5. Очистить поиск, выбрать «Информация»: появится сообщение об отсутствии описания.
6. Выбрать второй этаж: видны сообщения об отсутствии мест и подложки.
7. Открыть `/map/does-not-exist`: «Площадка не найдена».
8. Проверить на узком экране; список располагается ниже карты, карточка прокручивается в область просмотра.

## Проверки и ограничения

Команда всех проверок:

```powershell
node --check src/visitor/visitor.js
node --check src/main.js
node --test test/venue-api.test.js test/venue-store.test.js test/visitor.test.js
```

`npm.cmd` в среде помощника не найден. Запущена эквивалентная команда Node из package.json плюс новый тест visitor. Сборки и линтера в проекте нет.

- Новые тесты viewer: **3/3 проходят** — сохранённое размещение/legacy-подложка; неподвижная точка при зуме и вписывание повёрнутых объектов на узком экране; HTTP-маршруты, ресурсы, 404 и закрытые серверные исходники.
- Полный набор: **10/12 проходят**. Два прежних теста подложки не согласованы с кодом в полученной копии:
  - `test/venue-api.test.js:456`: ожидает y=1/6 при высоте 5/6; центрирование в сервере даёт `(1 - 5/6) / 2`, примерно 1/12.
  - `test/venue-store.test.js:140`: портрет 600×1200 размещается с шириной 0.36 и высотой 1; для холста 1000×600 это нарушает пропорции, сервер отклоняет данные (соответствующая ширина была бы 0.30).
  Эти тесты и серверная геометрия не изменялись в задаче visitor. Общий набор нельзя считать полностью зелёным.
- В браузере проверены настоящий GET сохранённого демо, подложка x=100/y=90/700×420/opacity=.7, выбор по карте и списку, описание и его отсутствие, поиск без учёта регистра, пустой результат, +/−, перетаскивание, общий вид, смена этажей, отсутствие мест/подложки, 404.
- Проверены desktop 1366×900 и мобильный viewport 390×844: нет горизонтального переполнения, измеренные кнопки ≥44 px. Это эмуляция ширины, не физический телефон.
- Отсутствие PNG проверено временным переименованием только созданного демо-файла; после проверки файл восстановлен. Объекты и места оставались доступны.
- Сетевая ошибка проверена временным локальным прокси с разрывом соединения: сообщение об ошибке и «Попробовать снова»; после восстановления кнопка успешно загрузила карту. Прокси остановлен и его временные исходники удалены.
- Жест двумя пальцами реализован через Pointer Events, но на физическом сенсорном устройстве не проверен. Остаётся ручная проверка pinch на телефоне. Состояние загрузки реализовано; отдельный длительный slow-network сценарий не записывался.
- Маршруты, геолокация и просмотр 3D-панорам не добавлялись. В полученном проекте `src/panorama/` пуст; API панорам содержит только id/name/x/y, без медиа и проекции. Массивы панорам/маршрутов не меняются. Подключение будущего просмотрщика потребует согласовать его контракт.
- Изменения конструктора, которые другой агент делает после создания этой копии, автоматически сюда не попадают. Перед объединением сверить изменения контракта.

## Для участника, который добавляет визуал

Начать с `src/visitor/visitor.css`. Цвета, шрифт Arial, размеры и адаптивные сетки находятся здесь; стили ограничены `.visitor` и `body.visitor-page`.

Сохранять `data-*` атрибуты, используемые в visitor.js, и семантику button/input/select. Не использовать названия мест как HTML. У маркеров минимум 44×44 px независимо от зума; позиция центра вычисляется в пикселях из той же камеры, что преобразует SVG. Не добавлять отдельное масштабирование фонового изображения или независимый CSS transform для слоёв. У `.visitor-viewport` сохранять `position: relative`, `overflow: clip` и `touch-action: none`; у SVG и слоя маркеров — общую область. `overflow: clip` предотвращает внутреннюю автопрокрутку к маркерам вне экрана при фокусе.

Карточка расположена рядом с картой на компьютере и ниже неё на телефоне; выбор переводит фокус на карточку, закрытие возвращает его к исходной кнопке. Сохранить состояния ошибок, различие demo/API, видимые фокусы, aria-pressed и кнопку общего вида. После замены визуала повторить ручной сценарий выше.
