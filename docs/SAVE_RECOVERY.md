## Статус

Исправление ошибки 400 в текущей несохранённой карте пользователя ещё не подтверждено. Ответ и тело её PUT, а также вывод обслуживающего процесса не были доступны помощнику. Текущий код сервера не записывает ожидаемые ошибки 400 в console; подробность возвращается в JSON `error`/`message`. Прошлые тесты не доказывают сохранение этой карты.

Текущий код конструктора отправляет `{name, floors}` и кавычки вокруг `If-Match`. В открытой вкладке отображается другой текст ошибки, поэтому она может исполнять предыдущую версию или временный обработчик. Не считать это доказательством конкретной причины 400.

## Уже открытая вкладка

Не обновлять и не закрывать её, не перезапускать сервер.

В Console инструментов разработчика **самой страницы карты** (контекст с адресом `/constructor`, не окно расширения VS Code) выполнить:

```js
import('/src/constructor/constructor.js?recovery=20261024').then(m => m.installSaveRecovery())
```

Команда загружает дополнительный обработчик и стили. Она не монтирует конструктор заново, не читает ключ и не сбрасывает состояние карты.

1. Нажать существующую кнопку «Повторить сохранение» или «Сохранить». Ключ при необходимости вводить только в локальное поле.
2. Нижняя панель покажет фактический ответ PUT. Данные карты из этой попытки станут доступны для выгрузки.
3. Нажать «Выгрузить карту и подложку в JSON» и проверить файл в Загрузках. Он содержит данные объектов и изображение подложки, без заголовков авторизации. Если файл подложки недоступен, выгрузка выдаст ошибку — не считать резервную копию готовой.
4. Обработчик может повторить запрос автоматически только после точного ответа сервера: лишние служебные поля верхнего уровня либо отсутствие кавычек вокруг того же номера версии. Он не удаляет настройки подложки, не исправляет геометрию наугад и не подменяет номер версии последней серверной версией.
5. При другой ошибке передать помощнику только `error` и `message`. Не копировать Headers, Authorization, cURL или полный HAR.
6. Только после PUT 200 открыть тот же URL площадки **в новой вкладке**, ввести ключ локально и сравнить подложку и объекты. Исходную вкладку сохранять до проверки.

Если ошибка означает несовместимость уже работающего сервера с новым форматом, сначала получить и проверить локальный JSON, затем отдельно согласовать дальнейшее действие. Перезапуск автоматически не выполняется.

## Изменения интерфейса

- Верхняя панель и инструменты переносят кнопки на новые строки; длинная ошибка не скрывается многоточием.
- «Выгрузить JSON» экспортирует текущую карту с изображениями подложек. Формат `space-map-recovery-v1`: `payload` содержит `{name,floors}`, `backgrounds` содержит изображения в data URL. Автоматический импорт пока отсутствует.
- «Удалить подложку» сохраняет `background: null` тем же PUT, что и объекты. При отказе остаётся несохранённое изменение, которое можно отменить или повторить. Физический файл подложки не стирается этой операцией.
- «Поделиться» остаётся отключённой с пояснением. Отдельный visitor-viewer не подключался.
- Эти кнопки доступны при новом открытии конструктора. Подключение восстановления к старой вкладке добавляет только панель восстановления и обновляет CSS; уже загруженный конструктор не заменяется.

## Проверки

На изолированном сервере и тестовой карте проверено в браузере:

- неверный ключ → отказ 401 → локальный ввод тестового ключа → повтор в той же вкладке → PUT 200;
- новая вкладка загружает сохранённый объект и подложку;
- JSON скачивается, содержит объект и изображение PNG, не содержит ключ или заголовки;
- удаление подложки сохраняется после повторного открытия, объект остаётся;
- панели при ширине 1100 и 640 пикселей доступны;
- временный тест старого формата PUT получает 400, обработчик исправляет только подтверждённые дефекты формата и возвращает 200 без перезагрузки документа.

`node --test test/venue-api.test.js test/venue-store.test.js test/save-recovery.test.js`: 12 тестов прошли. Новые тесты проверяют настоящий ответ 400 и повтор, сохранность объектов/подложки, сохранение удаления и повторное чтение хранилища, отказ от исправлений при конфликте версии и неизвестных полях.

Реальная несохранённая карта пользователя, Network её вкладки и серверный лог требуют отдельной проверки. Push, deploy, reset, clean и перенос visitor-viewer не выполнялись.
