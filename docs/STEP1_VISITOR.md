# Шаг 1. Связь конструктора с картой посетителя

Состояние на 24.10.2026: изменения внесены в копию присланного архива и **не опубликованы на Aeza или GitHub**.

## Проверить в уже работающем Node.js окружении

1. Распакуйте проект отдельно от действующей серверной папки. Не удаляйте `DATA_DIR` с площадками и подложками.
2. Из каталога проекта выполните `npm test`: ожидается 13 успешных тестов. Затем запустите его с настроенным `ORGANIZER_TOKEN` через `npm start`.
3. Откройте `/constructor`, создайте или откройте площадку, добавьте место «Вход», нажмите «Сохранить».
4. Нажмите «Ссылка на карту», скопируйте адрес `/map/<ID>` и откройте его в другой вкладке или на телефоне через адрес сервера. Убедитесь, что название и «Вход» совпадают с сохранёнными.
5. Старые адреса `/map/demo` и `/editor/demo` ведут на `/map` и `/constructor`. Они больше не открывают заглушки.

На локальном компьютере адрес с `localhost` виден только ему. Для проверки телефоном используйте адрес работающего сервера Aeza **после развёртывания этой версии**. Перед обновлением Aeza участник 1 должен объединить изменения с актуальной рабочей веткой, сохранить копию `DATA_DIR`, проверить токен и `npm test`, затем обновить код и перезапустить службу. Простого `git push` недостаточно.

В интерфейсе показывается один план: `floors[0]` сохранён как внутренний формат совместимости. Путь показывается только если в данных есть узлы с `placeId` и соединяющие их рёбра; редактор этих связей будет следующим шагом. Точки панорам в JSON пока могут иметь только имя и координаты: прикрепление изображения и склейка составляют отдельный следующий шаг.
