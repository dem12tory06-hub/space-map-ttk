# Передача конструктора организатора участнику 1

Этот архив — проверяемая рабочая копия прототипа, а не команда на публикацию. Пока достаточно распаковать его в отдельную папку, изучить изменения и согласовать объединение с актуальным GitHub. Папку работающего сайта Aeza не заменять.

## Что внутри

- `src/constructor/` — интерфейс организатора: план, объекты, места, проверка автоматического маршрута и необязательные предпочтительные участки.
- `src/shared/` — цели навигации и расчёт пути вокруг стены, сцены и стенда. Зона остаётся проходимой.
- `src/visitor/visitor-map.js` — функция `plannedRoute`, которую сейчас использует и конструктор для проверки пути; при объединении сохранить эту зависимость либо перенести функцию в общий модуль.
- `server/venue-store.js` — схема площадки: один видимый план (`floors[0]`), Wi-Fi как точка с полями `wifiLogin` и `wifiPassword`, совместимость со старыми точками Wi-Fi с текстом в `description`.
- `server/app.js`, `src/main.js`, `index.html` — маршруты страниц и раздача публичных модулей. Сравнить с актуальными версиями в Git перед объединением.
- `preview-windows.cmd` и `preview-local.py` — временный предпросмотр на Windows без Node.js. На Aeza не нужны.

## Как проверить отдельно

1. На компьютере с Node.js 24 или новее открыть распакованную папку `space-map-ttk` и выполнить `npm test` (ожидается 21 успешный тест).
2. Либо на Windows с Python запустить `preview-windows.cmd`, открыть `http://127.0.0.1:8765/constructor` и ввести ключ `preview`. Данные этого предпросмотра существуют только пока открыто его окно.
3. Создать площадку, поставить вход, регистрацию, Wi-Fi, стену и сцену. У точки Wi-Fi заполнить логин (название сети) и пароль; проверить карточку посетителя по «Ссылке на карту».
4. Во вкладке «Маршрут» выбрать начало и конец и проверить обход препятствий. Рабочая зона проходима. Ручные изгибы необязательны; сеть сохранённых участков видна организатору только по запросу.

## Объединение позже

Сравнить файлы с текущей веткой проекта, особенно общие `server/`, `src/main.js`, `index.html` и `src/shared/`; переносить изменения выборочно с учётом новых правок команды. Существующие данные площадок, `DATA_DIR`, переменные окружения, ключ организатора и настройки службы не входят в архив. Прежде чем публиковать на Aeza, отдельно проверить сохранение и чтение на тестовой площадке, а затем карту посетителя на телефоне. GitHub и Aeza сами по себе не обновляются от получения этого ZIP.

Загрузка и серверная склейка панорам в этом прототипе ещё не подключены. Функции интерфейса посетителя будут дорабатываться отдельно.
