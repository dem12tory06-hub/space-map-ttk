# Карта пространства — основа проекта

Кейс ТТК. Этап 1: общий проект, запускаемый сервер и общая страница.

## Запуск на Windows

1. Распаковать архив в отдельную папку, например `D:\Projects\space-map-ttk`.
2. В VS Code выбрать **Файл → Открыть папку** и открыть папку, в которой лежит `package.json`.
3. Открыть **Терминал → Создать терминал** и выполнить:

```powershell
node --version
$env:ORGANIZER_TOKEN = [guid]::NewGuid().ToString('N')
npm.cmd start
```

Нужен Node.js 24 или новее. `npm install` для этого этапа не нужен: внешних зависимостей нет.
В браузере открыть http://localhost:3000. Для остановки — Ctrl + C в терминале.
Отдельная страница ручной проверки API: http://localhost:3000/test/venue.
Отдельный конструктор площадки: http://localhost:3000/constructor.
Для автоматической проверки: `npm.cmd test`. На Ubuntu команда запуска: `npm start` или `node server/index.js`.
Без `ORGANIZER_TOKEN` API чтения работает, но создание и изменение площадок отключены.
Не вставляйте токен в клиентский код. Для удалённого доступа передавайте его только через HTTPS.

Сервер слушает сетевые интерфейсы; для удалённого доступа настройте firewall и HTTPS.
Публикация этого проекта в Git не обновляет Aeza автоматически.

## Что есть

- Общая страница с переходами на экраны-заготовки.
- Маршруты `/`, `/map/demo`, `/editor/demo`.
- Проверка ответа серверной программы: `/api/health`.
- API создания, загрузки и сохранения площадок; изменения защищены Bearer-токеном и проверкой версии.
- JSON-хранилище вне каталога проекта (`~/.local/share/space-map-ttk/venues.json`); путь можно задать через `DATA_DIR`.
- Папки под части команды и черновик соглашения по данным.
- Раздаются только явно перечисленные публичные файлы; серверные исходники по HTTP недоступны.

## Границы текущего этапа

- `/editor/demo` остаётся прежним демонстрационным редактором; рабочий прототип конструктора доступен отдельно по `/constructor`.
- Visitor-viewer по `/map/<venueId>` пока не подключён; маршрут показывает уведомление, а не готовую карту.
- Полноценного входа организатора и системы пользователей нет: используется общий Bearer-ключ из переменной окружения.
- Маршруты по проходам, просмотр панорам и склейка кадров не реализованы.
- Публикация текущей локальной версии на Aeza не подтверждена.

Подложки JPG/PNG хранятся отдельными файлами в `DATA_DIR/backgrounds/`; локальная ссылка `/map/<venueId>` сама по себе не является публичной ссылкой.

## Кто редактирует файлы

| Путь | Владелец | Назначение |
| --- | --- | --- |
| `server/` | Участник 1 | Сервер, далее сохранение, доступ и обработка |
| `src/main.js` | Участник 1 | Общая страница и подключение экранов |
| `src/api/` | Участник 1 | Будущие запросы загрузки и сохранения |
| `src/shared/` | Участник 1 после согласования с командой | Общий формат данных |
| `src/styles/base.css` | Участник 1 после согласования стиля | Общие стили |
| `src/editor/` | Участник 2 | Редактор организатора и его стили |
| `src/visitor/` | Участник 3 | Экран посетителя и его стили |
| `src/panorama/` | Участник 3 | Съёмка и просмотр панорам |
| `package.json`, `index.html`, `.gitignore`, `docs/` | Участник 1 | Общая конфигурация и договорённости |

Папки с `.gitkeep` зарезервированы и ещё не содержат компонентов.
Стек интерфейсов участников 2 и 3 неизвестен. Сначала изучить их файлы; затем участник 1
подключает экраны или добавляет нужную сборку. Не переносить и не переписывать их код автоматически.

## GitHub и совместная работа

Репозиторий в аккаунте команды ещё нужно создать. Архив не содержит `.git` и не связан с GitHub.
Пароли, токены, `.env`, рабочие базы и пользовательские фотографии не добавлять в репозиторий.
Текущий `.gitignore` исключает `data/`, `uploads/`, `.env` и зависимости.

После создания репозитория: основная ветка `main`, рабочие ветки `feature/editor`
и `feature/visitor`. Общую конфигурацию и объединение контролирует участник 1.

## Следующие проверяемые шаги

1. Запустить основу на Windows и отправить её в GitHub.
2. Согласовать данные и подключение с участниками 2 и 3 по фактическим файлам.
3. Добавить серверное хранение, чтение и сохранение карты.
4. Добавить вход организатора и проверку каждого запроса изменения данных.
5. Подключить маршрут по вручную размеченным проходам и интерфейсы участников.
6. Опубликовать на Aeza, проверить на телефоне и записать демонстрацию до сдачи слайдов 25 октября в 11:30–12:00 по Москве.

Склейку серии кадров проверить отдельным ранним экспериментом. Загрузка готовой панорамы её не заменяет.
