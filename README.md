# Карта пространства

Кейс ТТК. Конструктор и карта посетителя используют одну площадку по ID.

Проверка автоматических маршрутов и локальный просмотр на Windows описаны в [docs/STEP2_ROUTES_AND_PREVIEW.md](docs/STEP2_ROUTES_AND_PREVIEW.md).
Чтобы посмотреть интерфейс без установки Node.js, запустите `preview-windows.cmd` и откройте `/constructor` по адресу, который появится в окне.

## Запуск на Windows

1. Распаковать архив в отдельную папку, например `D:\Projects\space-map-ttk`.
2. В VS Code выбрать **Файл → Открыть папку** и открыть папку, в которой лежит `package.json`.
3. Открыть **Терминал → Создать терминал** и выполнить:

```powershell
node --version
$env:ORGANIZER_TOKEN = [guid]::NewGuid().ToString('N')
npm.cmd start
```

Нужен Node.js 24 или новее. `npm install` для этого этапа не нужен: внешних зависимостей нет.
В браузере открыть http://localhost:3000. Для остановки — Ctrl + C в терминале.
Отдельная страница ручной проверки API: http://localhost:3000/test/venue.
Отдельный конструктор площадки: http://localhost:3000/constructor.
Для автоматической проверки: `npm.cmd test`. На Ubuntu команда запуска: `npm start` или `node server/index.js`.
Без `ORGANIZER_TOKEN` API чтения работает, но создание и изменение площадок отключены.
Не вставляйте токен в клиентский код. Для удалённого доступа передавайте его только через HTTPS.

Сервер слушает сетевые интерфейсы; для удалённого доступа настройте firewall и HTTPS.
Публикация этого проекта в Git не обновляет Aeza автоматически.

## Что есть

- Главная страница `/`, конструктор `/constructor`, карта посетителя `/map/<venueId>`.
- `/map` открывает карту по ID; старые demo-адреса перенаправляют на рабочие страницы.
- Проверка ответа серверной программы: `/api/health`.
- API создания, загрузки и сохранения площадок; изменения защищены Bearer-токеном и проверкой версии.
- JSON-хранилище вне каталога проекта (`~/.local/share/space-map-ttk/venues.json`); путь можно задать через `DATA_DIR`.
- Папки под части команды и черновик соглашения по данным.
- Раздаются только явно перечисленные публичные файлы; серверные исходники по HTTP недоступны.

## Границы текущего этапа

- Редактирование ведётся в `/constructor`; старые файлы демонстрационного редактора удалены.
- Посетитель видит первый план, сохранённые объекты и места; может выбрать начало и конец в любой доступной точке плана. Маршрут автоматически обходит стены, сцену и стенды. Вкладка «Маршрут» позволяет проверить путь; предпочтительные участки необязательны.
- Полноценного входа организатора и системы пользователей нет: используется общий Bearer-ключ из переменной окружения.
- Организатор может загрузить готовый JPEG в точку панорамы или отправить серию снимков на локальный Python worker через `/panorama-capture`. Просмотрщик поддерживает оба формата изображения; кадры серии не сохраняются в JSON площадки.
- Для склейки на Aeza нужен отдельный сервис из `deploy/space-map-panorama.service` и зависимости `panorama-requirements.txt`. Без него прежняя загрузка готового JPEG продолжает работать.
- Новая площадка манежа лежит в `fixtures/manege-venue.json`; её добавляют в серверное хранилище скриптом `tools/import-manege-venue.mjs` только после резервной копии и остановки приложения. Скрипт не заменяет уже существующие площадки.
- Публикация этой рабочей версии на Aeza подтверждается отдельно после проверки запущенного сервера.

Подложки JPG/PNG хранятся отдельными файлами в `DATA_DIR/backgrounds/`; локальная ссылка `/map/<venueId>` сама по себе не является публичной ссылкой.

## Кто редактирует файлы

| Путь | Владелец | Назначение |
| --- | --- | --- |
| `server/` | Участник 1 | Сервер, далее сохранение, доступ и обработка |
| `src/main.js` | Участник 1 | Общая страница и подключение экранов |
| `src/api/` | Участник 1 | Будущие запросы загрузки и сохранения |
| `src/shared/` | Участник 1 после согласования с командой | Общий формат данных |
| `src/styles/base.css` | Участник 1 после согласования стиля | Общие стили |
| `src/constructor/` | Команда | Действующий конструктор и его стили |
| `src/visitor/` | Участник 3 | Экран посетителя и его стили |
| `src/panorama/` | Участник 3 | Съёмка и просмотр панорам |
| `package.json`, `index.html`, `.gitignore`, `docs/` | Участник 1 | Общая конфигурация и договорённости |

При объединении с работой остальных участников нужно проверить различия в общих файлах и сохранить серверные данные вне каталога кода.

## GitHub и совместная работа

Исходная рабочая копия проекта получена из архива команды. Этот архив проверки не содержит `.git`, паролей, токенов, `.env`, рабочих баз и пользовательских фотографий. Изменения архива ещё не опубликованы в GitHub или на Aeza. Участник 1 объединяет их с актуальной версией репозитория и отдельно обновляет сервер.

## Следующие проверяемые шаги

1. Локально проверить создание площадки, объекты, места и автоматический путь на `/constructor`.
2. Открыть ссылку `/map/<venueId>` в том же локальном предпросмотре и проверить путь между свободными точками.
3. Участнику 1 объединить код с актуальным GitHub, отдельно проверить `npm test` и обновление данных площадок.
4. После публикации на Aeza повторить проверку на телефоне; подтвердить сохранение после перезагрузки сервера.

Склейку серии кадров проверить отдельным ранним экспериментом. Загрузка готовой панорамы её не заменяет.
